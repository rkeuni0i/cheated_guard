# ADR-001: 스트리밍 인프라(Kafka/Flink) 미도입

## 상태
채택 (Accepted)

## 맥락
"실시간 이상탐지"라는 말 때문에 Kafka·Spark·Flink를 먼저 도입하기 쉽다. 하지만 이
시스템의 실시간 요구는 **"거래 1건당 3초 이내"** 이지 *"초당 10만 건 처리"* 가 아니다.
단건 저지연과 대용량 처리량은 전혀 다른 문제다.

## 결정
스트리밍 인프라를 쓰지 않는다. 인터페이스만 이벤트 지향으로 설계해 교체 가능하게 둔다.
- 프로덕션 권장: PostgreSQL 16 + Redis 7 (PRD 3.4).
- 본 자족형 구현: SQLite(영속) + 인메모리 슬라이딩 윈도우(벨로시티). 외부 서비스 의존
  없이 알고리즘·정책·백테스트를 그대로 증명한다.

## 포기한 것
초당 수만 건 확장성(인터페이스로 여지 확보). 프로덕션 전환 시 Redis ZSET/Kafka로 교체.

## 결과
`spendguard/features/velocity.py`는 Redis ZSET과 동일한 의미(슬라이딩 윈도우, 조회 후
기록으로 누수 방지)를 인메모리로 구현한다. `spendguard/db.py`는 PostgreSQL DDL의 의미
(멱등 유니크 인덱스, append-only 프로파일, 재현성 버전 기록)를 보존한다.
